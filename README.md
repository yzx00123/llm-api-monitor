# ⚡ LLM API Monitor

大模型 API 实时监测器 —— 一个桌面端（Electron）工具，用于监控主流大模型 API 的可用性、实时延迟、密钥有效性与账户余额。

![tech](https://img.shields.io/badge/Electron-33-47848F) ![react](https://img.shields.io/badge/React-18-61DAFB) ![ts](https://img.shields.io/badge/TypeScript-5-3178C6)

## 功能

- **实时监测**：按可配置间隔（5 秒 ~ 24 小时，含自定义）轮询各厂商 API，每次只发 `hi` + `max_tokens=1` 的极简请求，既测真实往返延迟又把探测成本压到最低
- **429 自动退避**：被厂商限流时按 `Retry-After`（或指数退避，最长 15 分钟）暂停这把密钥的探测，期间不误报掉线、不给厂商添压，卡片显示「限流 HH:MM」徽标
- **多协议支持**：OpenAI 兼容协议、Anthropic Messages API、Google Gemini API
- **内置 21 家厂商**：OpenAI / Claude / Gemini / Groq / xAI (Grok) / DeepSeek / Kimi (月之暗面) / 通义千问 / 智谱 GLM / 百川 / MiniMax / 零一万物 / SiliconFlow / 讯飞星火 / 阶跃星辰 / 豆包 (火山引擎) / Mistral / Together / Perplexity / OpenRouter / 小米 MiMo
- **自定义供应商**：支持添加任意兼容接口（名称 / 地址 / 协议 / 余额接口 / 模型列表）
- **密钥智能识别**：批量粘贴或文件导入（JSON/CSV），密钥自动实测归属厂商；无法识别时弹窗手动分配
- **余额查询**：DeepSeek、Kimi（按官方文档对接）、SiliconFlow 等支持余额接口的厂商；小米 MiMo 需要登录控制台，按小米账号分别记录（多个账号的余额互不串号）
- **百炼免费额度**：阿里云百炼的免费额度按模型发放（每个模型 100 万 Token、90 天），官方没有查询接口 —— 登录一次控制台后，账单页按模型列出剩余额度 / 发放总量 / 余量进度条 / 到期时间 / 用完即停状态，仪表盘的通义千问卡片显示「免费 N 个」汇总
- **数据持久化**：密钥与自定义供应商通过 electron-store 落盘，重启不丢失；账单明细单独存 gzip 文件（实测两天数据 160 KB → 9 KB），配置永远只有几 KB
- **告警通知**：掉线 / 余额不足弹系统通知（可开关、可静音、可关恢复提醒），60 秒冷却防轰炸
- **延迟迷你曲线**：每个密钥格子显示最近 30 次探测延迟走势
- **系统托盘 + 后台驻留**：关窗不退出，监测继续，托盘一键唤出（可关）
- **状态快照导出**：一键导出所有密钥状态为 CSV（带 BOM，Excel 直接打开不乱码）
- **消费账单**：按天统计每家厂商花了多少钱，折线图 / 柱状图 / 树状图切换，可导出 CSV；token 用量全厂商通用（统计本软件探测自身消耗）
- **导出到 Agent**：一键把密钥写进 19 个 AI 编码 Agent 的配置（Claude Code / Codex / Gemini CLI / Cursor / OpenClaw / DeepSeek Harness …）；写入前显示将要写入的完整文件内容，写入后回读校验，只改自己那一条、保留别人的配置与注释。每个通道标注可信度（已验证 / 有官方文档 / 未验证），协议不匹配时直接拒绝而不是写一份用不了的配置
- **应用内使用说明**：设置 → 使用说明，含快速上手三步、界面说明与常见问题
- **低资源占用**：禁用 GPU 加速 + V8 堆上限 + 隐藏时主动 GC，前台 ~156 MB / 后台 ~148 MB

## 运行

```bash
npm install
npm run dev      # 开发模式（热更新）
npm run build    # 构建到 out/
```

构建产物直接用 Electron 运行：

```bash
./node_modules/.bin/electron out/main/index.js
```

> Windows 下若提示 Electron 安装不完整，删除 `node_modules/electron` 后重新 `npm install`；
> 若 `ffmpeg.dll` 缺失，从 `%LOCALAPPDATA%\electron\Cache` 中的发行包重新解压补齐。

## 发布

一次完整的发版（改 `package.json` 版本 + 在下方更新日志加一节之后）：

```bash
npm run ship     # = build + dist + release
```

- `npm run dist` 生成 `release/LLM-API-Monitor-Setup-<版本>.exe`
- `npm run release` 把安装包上传到 GitHub Releases（正文取自本文件对应版本的更新日志）
- 只补传某个历史版本的包：`npm run release -- 1.3.7`（要求 `release/` 里已有该版本的 exe）
- 凭据复用 git push 的凭据（Windows 凭据管理器），也可以临时用 `GITHUB_TOKEN` 环境变量覆盖
- 改过「导出到 Agent」的通道定义后，跑 `npm run check:agent` 自检：它会在临时 HOME 里伪造
  19 个 Agent 全部已安装 + 都已有用户配置，逐个预演 / 写入 / 回读校验，再跑一遍协议矩阵
  （Claude Code、Codex、Gemini CLI × 各协议密钥），全过才退出码 0
- 代码推送：平时 `git push`；如果连不上 `github.com:443`（`Recv failure: Connection was reset` /
  `Failed to connect to github.com:443`）而 `api.github.com` 仍然通，可以用
  `npm run push:api` 走 GitHub API 推送当前 HEAD——它会复刻本地提交的全部字段，
  远端 commit sha 与本地完全一致，网络恢复后不会出现分叉。加 `-- --dry-run` 可以先演练。

## 设计说明

- **密钥安全**：密钥仅存储在本地 `%APPDATA%` 的 electron-store 配置中，不经过任何第三方服务器
- **并发控制**：监测引擎最多同时 5 个探测请求，超出排队，防重入
- **每家厂商的余额接口格式不同**，解析逻辑基于实测（DeepSeek）与官方文档（Kimi）对接，其余厂商做防御性解析

## 已知限制

- 每次探测只消耗 1 个 token 左右（`hi` + `max_tokens=1`；延迟测量不受影响），默认 10 秒间隔下单把密钥约 360 tokens/小时
- 部分厂商无公开余额接口（如智谱），余额显示 "—"
- 阿里云百炼的免费额度只存在于控制台里，没有对外查询 API：需要点一次「登录百炼控制台」（cookie 存本地独立分区），之后软件才能读到每模型剩余额度；未登录时账单页会明确提示，而不是显示 0
- Azure OpenAI / AWS Bedrock 的签名认证暂未支持

- 修复：提示如实汇报「新建供应商 M 个（名字）」「跳过 K 条无法识别的记录」「都已存在，没有新增」，不再拿解析到的行数当成功数。

### v1.5.0

这一版新增「阿里云百炼免费额度」：百炼的免费额度是按模型一个个发的（每个模型 100 万 Token、90 天有效），散在控制台的一张大表里，软件里现在能直接看到还差多少。

- 新增：**账单页「阿里云百炼免费额度」区块**。登录一次控制台后，按模型列出：剩余额度 / 发放总量、余量进度条与百分比、到期时间（含「剩 N 天」「已过期」）、用完即停开关状态；顶部四张汇总卡对应控制台的「有额度模型总数 / 使用率 >50% / >80% / 剩余 Token 合计」。已用尽或已过期的模型也留在表里（排到最后、标「已用尽」），一眼能分清「没开通」和「花完了」。
- 新增：**仪表盘通义千问卡片显示「免费 N 个」徽标**，悬停列出前 5 个模型的剩余额度与总量，不用切到账单页也能知道还有多少免费额度可以用。
- 说明：百炼官方文档没有给出任何「按模型查剩余额度」的 API（只在控制台展示）。这里走的是控制台自己的内部接口（`queryFreeTierQuotaAsyn` 异步任务 + 轮询），所以必须**登录一次**：点「登录百炼控制台」会弹出控制台窗口，登录成功后窗口自动关闭、数据立刻刷新。cookie 只存在本机独立分区（`persist:bailian-console`），点「退出登录」即清空，任何数据都不上传。
- 修复：**未登录时不再显示成「接口出错」**。裸会话请求网关只会回一段 `Bad Request`，旧逻辑会把这段当成解析失败；现在先看分区里有没有阿里云登录态 cookie，没有就直接提示「还没登录百炼控制台」，也省掉 5 次白打的请求。
- 修复：**登录窗口打开控制台首页而不是免费额度深链**。深链在未登录时停在空白页，用户找不到登录入口；首页会自己判断登录态并跳转阿里云 SSO。
- 修复：**请求头不能手工设 `origin` / `referer`**。Electron 的 `session.fetch` 手动塞这两个头会被 Chromium 网络栈直接拦掉（`net::ERR_BLOCKED_BY_CLIENT`），网关只认会话 cookie，去掉后正常。
- 验证：本地假网关复刻了「异步任务 + 轮询 + 5 个模型大类」的完整流程，端到端跑通 —— 5 个模型（82% / 32% / 50% / 99% / 0% 已过期）逐条解析正确，账单页表格 5 行、汇总卡「剩余 263 万 / 共发放 500 万」、通义千问卡片「免费 2 个」徽标与 tooltip 均正确。

### v1.4.5

这一版改的是「延迟到底在测什么」：以前测到的是模型把整句话生成完的时间，现在测的是收到第一个 token 的时间。

- 优化：**延迟改为「首字延迟」（TTFT）**。旧版探测用 `stream:false`，而多数网关（Moonshot 尤其明显）会等整段回复生成完才发响应头 —— 同一把 key 实测非流式 1.85~2.0s、流式首块 0.99~1.28s，卡片上那个「一秒多」其实是模型写完整句话的时间。现在探测改成 `stream:true`，收到第一个数据块就停（顺手 `cancel` 掉剩余流量），显示的是用户真正感知的响应速度。
- 优化：**不认流式的网关自动回退**。少数兼容网关收到 `stream:true` 会直接 400，这时自动改回非流式探测，并记住这家厂商（之后不再白打一次流式请求），功能与之前完全一致。
- 优化：**卡片悬停给出中位数**。单次采样容易撞上上游抖动（同一把 Kimi key 实测 0.99s ~ 9.85s 都出现过），悬停延迟数字可以看到最近 N 次的中位数，比单点更可信。
- 修复：**探测 token 记账不因流式而丢**。流式响应里网关常常只在最后一帧给 `usage`，现在会从事件流里解析累加；确实拿不到时按「1 token 输入 + 1 token 输出」估算，账本不会漏记。
- 说明：校准过测量本身 —— 本地假上游固定延迟 400ms，卡片读到 485ms；固定 500ms 时读到 508~560ms（多出来的是 fetch 与进程间开销），所以这个数字是可信的。

### v1.4.3

这一版只动存储：账单数据从主配置里搬出来，单独存 gzip。

- 压缩：**账本分离 + gzip**。余额 / 用量 / 探测流水原来全在 `llm-monitor-config.json` 里，实测用了两天就到 **160 KB**（余额样本 89 KB、用量样本 30 KB），而且每次采样都触发整个配置文件重写；现在明细单独写 `llm-monitor-config.history.json.gz`，主配置只剩密钥 / 会话 / 设置 —— 同一份数据实测 **159,739 字节 → 2,348 字节 + 6,994 字节**，总体积降了 **94%**，而账单逐日数字与迁移前完全一致。

### v1.4.2

这一版是「把整个应用翻一遍找 bug」，改动都在底层行为上，界面只多了一处提示：

- 修复：**删掉中间一把密钥后，后面的卡片状态整体错位**。状态表是按「第几把密钥」记账的，删掉第 2 把后第 3 把会继承它的余额/延迟/错误码，甚至继承它的 429 退避（最长 15 分钟不探测却显示「限流」）；现在按密钥本身重绑，被删那把的条目彻底丢弃。
- 修复：**点「停止」后仍会继续探测一轮**。已排队的供应商不会被清掉，队列还会自己往下发探测请求（每次都是真打上游、花 token）；现在停止会清空队列，且出队前再确认监测仍是开启状态。
- 修复：**测延迟失败一次就被判掉线**。测延迟页失败（超时 / 429 / 抖动）会把在线卡片直接打成异常并触发掉线通知，绕过了「连续 3 次失败才判定」的门限；现在测延迟失败只更新延迟数字，不改在线状态。
- 修复：**被限流的密钥会发假的「已恢复」通知**。429 分支原来把状态写成 idle，已弹过掉线的密钥因此触发「✅ 已恢复」并把配对记录删掉，真恢复时反而漏报；现在限流不改变稳定状态，只更新退避时间。
- 修复：**启动宽限期会把真实掉线吞掉**。宽限期内不弹通知是对的，但原来直接丢弃这次事件，而掉线事件只发一次——于是整个故障期既不报掉线也不报恢复；现在压到宽限期结束，仍未恢复就补报一次。
- 修复：**探测超时只覆盖了响应头**。10 秒超时在拿到响应头就被清掉，body 卡住时请求能吊几分钟，期间这张卡片一直停在「检测中」，若卡在余额查询还会让「没钱密钥的 10 秒轮询」整体失效；现在超时覆盖到读完 body。
- 修复：**金额是字符串时账本记不上**。有的厂商余额接口返回 `"0.88"` 这样的字符串，被数字类型校验挡掉，结果该厂商在账单里永远没有采样、今日消费恒 0；现在统一转成数字（DeepSeek 余额为 0 也不会再被当成「没数据」）。
- 修复：**余额接口 401/403 后卡片还挂着旧的正余额**（密钥被吊销了却显示有钱）；现在 401/403 会把余额清成未知，网络抖动等其它错误仍保留上次读数。
- 修复：**每次保存密钥都会把全部密钥重测一遍**（纯改个顺序也要真打一遍上游花 token）；现在只探「这次新导入的」。
- 修复：**托盘里的开始/停止与实际状态不一致**。托盘点完停止，窗口按钮还显示「停止」，重启后状态也和事实不符；现在开始/停止统一走一条路径，会把 `settings.enabled` 落盘并推送 `monitor:state`，托盘菜单每次弹出都按实际状态置灰。
- 修复：**导入的兼容性问题**：JSON 里没写 baseUrl 的条目会被塞进第一家厂商（`includes('')` 恒真）、CSV 导入因为逗号被吃掉恒为 0 条却提示成功；现在按厂商 id/名字匹配，CSV 按行解析并给出格式提示。导入文件还会自动识别 UTF-16 / GBK 编码。
- 修复：**自定义供应商的端点不再接受乱填**（自动补 `https://`、拒绝非 http(s)），编辑时也不会因为把类别改成「国内厂商」而变成不可编辑的只读卡片。
- 修复：**账单 CSV 的两个口径错误**：合计行用的是全时段总额（明细却只覆盖所选天数）、「累计」列实际写的是本月花费；都已改成和明细一致的全时段累计。
- 修复：**导出到别家配置文件时不再破坏用户原有设置**：Codex 的 TOML 只替换本工具那一段（以前会从标记行一路删到文件末尾，`[profiles.x]`、`[mcp_servers.*]` 全没了）；Claude Code / Gemini 只写本厂商的两个环境变量（以前一次覆盖 6 个键）；改任何配置文件前都会留一份 `*.llm-monitor.bak`。
- 修复：**采样写盘的放大**。以前每采一个点就把整个配置文件重写一遍（十几把密钥 × 每 10 秒一轮，40KB+ 的 JSON 一直在写）；现在攒 500ms 合批写一次，退出前同步刷盘。
- 修复：**更新监控状态/删除密钥后界面上的幽灵条目**：删掉自定义供应商后密钥表不重新拉取，下次保存会把已删供应商的密钥写回配置。
- 优化：小米控制台会话迁移加异常保护（迁移失败也不会让窗口建不出来）、已有会话时清掉旧字段（避免删光会话后老账号「复活」）、按「这次登录明确点的密钥尾号」优先归属。
- 优化：模态框支持 Esc 关闭；小米「登错账号」的提示改成卡片内提示，不再用阻塞式 `window.alert` 卡住整个界面刷新；「测延迟」的模型列表输入加了防抖（以前每敲一个字符就真发一次 `/models` 请求）。
